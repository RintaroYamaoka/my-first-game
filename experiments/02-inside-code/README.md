# 実験 2: コードの中を、本物の構文解析で読む

段階 1(技術検証)の 2 つ目の実験。捨てる前提のコード。

## 確かめたこと(2026-11-16)

| 問い | 結果 |
|---|---|
| TypeScript を正しく解析する部品が、Rust で使えるか | 使えた。`oxc_parser` 0.159(MIT ライセンス)。ビルドも速い |
| 関数・文・分岐・ループ・型・import まで読み取れるか | 読めた。実行すると、読み取った木が文字で出る |
| Web の試作で手書きしていた形(積層、分かれる分岐、輪のループ)を、本物のコードから自動で作れるか | 作れた |

## 動かし方

```
cd experiments/01-world-from-code/sample
cargo run -p inside-code -- src/store.ts src/server.ts test/parse.test.ts
```

Windows で動かす: `./scripts/run-windows.sh inside-code experiments/01-world-from-code/sample/src/store.ts ...`

操作: `←` `→` 回る / `↑` `↓` 上下 / `W` `S` 近づく・離れる。近づくと、板に元のコードの 1 行目が出る。

## 規則をどう実装したか

| 本物のコード | 形 | 大きさを決めるもの |
|---|---|---|
| 文 | 板 | 厚み = その文の行数 |
| ファイル、関数、ブロック | 板が、書かれた順に上から下へ積み重なる。線だけの枠で囲む | 中身の量 |
| 分岐(`if`、`try`) | 条件の下で、積層が横に分かれて、また一本に戻る。`else` がなければ、何もしない側の線だけが通る | — |
| ループ | 中身が輪になる | 輪の大きさ = 中身の量 |
| 型 | 線だけの枠 | 行数 |
| 式の中の関数(`test("...", () => { ... })`) | 文の板の下に、関数の積層が続く | — |

実行の流れは、板を貫く一本の線で表す。

## この実験で省略したこと

- **入れ子を縮小していない。** 「潜るとは、切り替えなしで拡大していくこと」(`prototypes/scape/`)の仕組みは入れていない。
  今は全部が同じ縮尺で見えている
- 呼び出し(`find(id)` から `find()` の定義へ伸びる線)を拾っていない。実験 1 のファイル間の線とつなぐ必要がある
- 値(変数の中身)は出していない。値は実行しないと分からない。本物の実行とつなぐのは、同梱する Linux の実験の後
- `switch`、クラス、`async`/`await` は、ただの文として扱っている
- 柱の面の陰影、線の太さ、名前の重なりは雑なまま
- 日本語を含むコードは、名前が正しく表示されない(同梱のフォントが英数字だけのため)
