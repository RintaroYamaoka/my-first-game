# 実験 7(音を重ねる): 一つの曲から分けたパートを、ずれなく重ねる・抜く・こもらせる

問い: 「パートが重なって一つの曲になる」仕掛けに要る 3 つ(ずれなく重ねる・抜く / 拍に合わせる / 深さでこもらせる・響かせる)が、
Rust の音の部品 kira でできるか。曲は、Suno で作って Studio からパートごとに書き出した物を使う。

## 仕組み

| 部分 | 担当 |
|---|---|
| 鳴らす | `kira` 0.12.6(MIT OR Apache-2.0)。Bevy の音の機能は使わず、Bevy は窓とキー入力だけ |
| ずれなく重ねる | 拍の時計(1 分に 100 拍)を作り、全パートを同じ拍に予約して鳴らし始める。入っていないパートも、音量を絞って鳴らし続ける |
| 拍に合わせる | 入れる・抜くの音量の動きを、次の小節の頭に予約する |
| こもらせる・響かせる | 全パートを一つの通り道にまとめ、そこに高い音を削る仕組みと残響を付ける。深さ 1 つの数値で両方を動かす |
| 曲の読み込み | FLAC を、少しずつ読みながら鳴らす(全部をメモリに広げると 7 パートで約 500MB になるため) |

kira の既定の機能のうち、dbus を使う部分(Linux 用)は外した。OS の部品を足さずに済む。

## 曲の元のファイル

`assets-src/suno/dive-test-01/`(git には入れない)。Suno の Premier の間に作って Studio から書き出した 13 本のうち、音が入っていた 7 本を FLAC にした物。
元の WAV は、本人の Windows の `Music\dive-test-01` にある。

## 動かし方

```sh
cargo run -p layers -- assets-src/suno/dive-test-01        # WSL の窓
cargo build -p layers --target x86_64-pc-windows-gnu       # Windows 用。layers.exe とパートのフォルダを Windows 側に置いて起動する
```

| 操作 | 動き |
|---|---|
| 1〜7 | パートを入れる・抜く(synth, bass, drums, percussion, keyboard, strings, fx の順) |
| 0 | 全部入れる・全部抜く |
| B | 入れる・抜くを、次の小節の頭まで待つか、すぐやるかを切り替える |
| ↑ ↓ | 深さ(↓ で深く。深いほど、こもって響く) |
| R | 最初から |

`REPORT=<秒>` を付けると、途中で全パートを入れ、その秒数のあとに状態を出力して終わる。

## 分かったこと(2026-11-20)

測って分かったこと:

- Suno の書き出しは 13 本(曲全体 1 本 + パート 12 本)。全部が同じ長さ(187.21 秒、48kHz、32 ビット)で、頭が揃っている
- 測った速さは 100 BPM。頼んだとおり
- 歌・コーラス・木管は無音。金管とギターは、ほぼ無音(数秒だけ小さな音)。使えるのは 7 本
- パートを全部足しても、元の曲と同じにはならない(音量を合わせても、元の曲より 11dB 小さい差が残る)。パートは、元の曲を切り分けた物ではなく、近い物
- パートを全部足すと、元の曲より約 2dB 大きく、頭が割れる。全体を 4dB 下げて鳴らしている
- kira で 7 パートを同じ拍から鳴らすと、再生位置のずれは 0(WSL と Windows の両方。10〜14 秒の時点)

本人が聞いて確かめること(まだ):

- パートを重ねたとき、音がきれいか。一つだけ鳴らしたとき、他の楽器の音が混ざっていないか
- 小節の頭で入る・抜くのが、気持ちよいか
- 深さのこもり方・響き方が、「潜る」に合うか
