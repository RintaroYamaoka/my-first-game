# 実験 1: 本物のコードから世界を組み立てる

段階 1(技術検証)の最初の実験。捨てる前提のコード。

## 確かめたこと(2026-11-16)

| 問い | 結果 |
|---|---|
| Rust + Bevy 0.20.1 がこの PC でビルドできて動くか | 動いた。最初のビルドは約 7 分半、作り直しは約 7 秒 |
| 本物のプロジェクトから世界を組み立てられるか | できた。`sample/`(本物の TypeScript と、`npm install` した本物の `node_modules`)を読み、柱と線にした |
| 「世界の形の規則」(`docs/concept.md`)が景色として成り立つか | 成り立つ。上下で依存の向きが読める。使われていない `unused.ts` は線がなく離れて浮く。自分で頼んだ 5 個の下に、頼んでいない 43 個が 4 層で連なる |

## 動かし方

```
cd experiments/01-world-from-code
cargo run -p world-from-code              # sample/ を読む
cargo run -p world-from-code -- <フォルダ>  # 別のプロジェクトを読む
```

操作: `←` `→` 回る / `↑` `↓` 上下 / `W` `S` 近づく・離れる

画面を 1 枚撮って終わる: `SHOT=out.png ANGLE=0.6 HEIGHT=1.5 DIST=15 cargo run -p world-from-code`

## 規則をどう実装したか

- 上下: ファイルは、頼っているファイルより必ず 1 層上。パッケージは足元で、自分のコードからの遠さ(1 = 自分で頼んだ・直接 import した)だけ下
- 水平: 線でつながるものは引き合い、すべては反発する。始まりの位置は名前から決まるので、毎回同じ形になる
- 柱の高さ: ファイルは行数。パッケージは中のファイル数(対数)

## この実験で省略したこと(次に確かめる)

- import を行の文字列から拾っている。本物の構文解析(関数、文、分岐、ループまで読む)は未着手
- 循環参照をまとめていない
- Node.js 組み込み(`node:fs` など)を世界に出していない
- ファイルを足したときに、周りの位置がどれだけ動くか(同じものは同じ場所にある、を守れるか)を見ていない
- 輪郭線は Bevy の簡易な線。太さと霞み方は仮
- **描画はソフトウェア(llvmpipe)で動いている。** WSL から GPU を使えていないので、速さと滑らかさはここでは測れない。
  測るには Windows 用にビルドして Windows で動かす必要がある
