# 実験 4: 世界の画面の上に、本物のターミナルを重ねる

問い(`docs/decisions/0002`): Bevy の上で、本物のターミナルの内容を表示し、キー入力を遅れなく通せるか。
`alacritty_terminal` は、使える形で公開されているか。ライセンスに問題はないか。

## 仕組み

| 部分 | 担当 |
|---|---|
| シェルを動かす(擬似端末)、画面の制御の解釈、マス目の管理 | `alacritty_terminal` 0.26.0(Apache-2.0)。crates.io に公開されている |
| マス目を描く | 自分で作った(`src/terminal.rs`)。色が同じ続きごとに、Bevy の文字として置く。変わった行だけ描き直す |
| キー入力 | 自分で作った。キーを、端末が受け取るバイト列に直して送る(Ctrl、Alt、矢印、Home / End など) |
| 世界 | 実験 2c(`04-worlds`)の写し。ターミナルを開いている間は、世界の操作を止める |

シェルは、渡したフォルダで起動する。Linux では `$SHELL`。Windows では、同梱の Linux がまだない(実験 5)ので、WSL のシェルを借りる。

## 操作

| 操作 | 動き |
|---|---|
| F1 / T | ターミナルを開く |
| F1 | 閉じる(Esc や Tab は、ターミナルの中で使うので、閉じるキーにしない) |
| Shift + PageUp / PageDown | 過去の出力へ戻る |

世界の操作は `04-worlds/README.md` と同じ。

## 動かし方

```sh
cargo run -p terminal -- experiments/01-world-from-code/sample           # WSL の窓
./scripts/run-windows.sh terminal experiments/01-world-from-code/sample  # Windows(GPU)
```

自動で打って 1 枚撮る(確かめるため):

```sh
TYPE='ls --color\necho 日本語\n' WAIT=4 SHOT=out.png cargo run -p terminal -- experiments/01-world-from-code/sample
```

## 分かったこと

- **動く。** 本物のシェルで `ls`、`git log`、色つきの出力、日本語の表示が通った(WSL の窓で、画面を撮って確認)。
- **日本語の文字**: Bevy の既定の文字は英数字だけ。実験では、パソコンに入っている文字のファイル(BIZ UD ゴシックなど)を
  起動時に読んで使っている。文字のファイルはリポジトリに入れていない。製品では、配ってよい等幅の文字を同梱する(未決)。
- **遅れ**: パネルの下に「キーを送ってから、その結果を画面に描くまで」の時間を出している。
  WSL の窓(ソフトウェア描画、約 24 fps)では約 44 ms で、ちょうど 1 コマぶん。つまり、遅れは描画の速さで決まる。
  Windows の GPU では約 200 fps(1 コマ 5 ms)で、本人が打って「普通に打てる」。
- 文字の折り返しを決める部品が、日本語のたびに「ICU4X data error」を端末に出す。表示には影響しない。製品では止める。

| 環境 | fps | キー → 画面 |
|---|---|---|
| WSL の窓(ソフトウェア描画) | 約 24 | 約 44 ms(1 コマ) |
| Windows(RTX 5070 Laptop) | 約 200(本人が確認) | 数字は未記録。本人「普通に打てる」 |

## 本人の感想(2026-11-17、Windows)

- ターミナルは開いた(WSL のシェルを借りる形で動く)
- 約 200 fps。普通に打てる
- 見え方(少し透けたパネルが世界に重なる)は「カッコいい」

## まだやっていないこと

- 日本語の入力(IME)、貼り付け、マウスでの選択
- 窓の大きさに合わせて、マス目の数を変える(今は 84 × 34 で固定)
- 太字・下線・点滅するカーソル
- ターミナルで起きたことを、世界に反映する(ファイルを作ると柱が立つ、など)。これは実験ではなく、ゲームの中心の仕組み
