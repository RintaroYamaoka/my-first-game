# 0002 — Rust で作る。エンジンは Bevy を本命にする

- **Status**: Accepted(Bevy で成立するかは段階 1 で確かめる。下の「未検証」を参照)
- **Date**: 2026-11-15
- **Deciders**: RintaroYamaoka (本人決定) / Claude
- **References**: [0001](0001-steam-first-local-runtime.md) の 2(画面は TypeScript + Three.js)と
  3(枠は Electron)を置き換える。1(Steam)と 4(本物の環境はプレイヤーの PC で動かす)はそのまま

## Context (背景)

0001 では画面を TypeScript + Three.js、枠を Electron とした。理由は、ターミナルとコードエディタの
完成品が使えることと、演出の作り直しが速いことだった。

その後、本人が判断の基準を示した。

> Rustが好き、ゲームとしての完成度。その両立。

長く続く開発で、本人が好きな技術であることには価値がある。完成度の面でも、ネイティブで作ると
起動の速さ、メモリ、キー入力から表示までの反応、動きの安定で有利になる。ターミナルが主役の
ゲームなので、入力の反応は体感に効く。

## Decision (決定)

1. **ゲーム本体は Rust で書く**
2. **エンジンは Bevy を本命にし、Windows 用のネイティブアプリとして作る**(Electron は使わない)
3. **Bevy の版は固定する。** 1.0 前で版ごとに書き直しが出るため、上げるのは段階の切れ目だけ
4. **演出の数値はコードに埋めない。** 速さ、間、色、カーブなどは、動かしたまま読み直せるファイルか、
   ゲーム内の調整画面に出す。作り直しの遅さ(下記)を補うため

## 受け入れる代償と、その補い方

| 代償 | 補い方 |
|---|---|
| ターミナル画面の完成品(xterm.js)が使えない | Rust 製の端末ソフトの中核部品(`alacritty_terminal`)を使い、表示だけ自分で作る。文字を 3D 世界の一部として演出できる利点にもなる |
| コードエディタの完成品(CodeMirror)が使えない | 本物の Linux なので、ターミナルの中で `vim` や `nano` が使える。加えて、初心者向けの簡単なエディタを用意する |
| 変更のたびにビルドが入り、演出の作り直しが遅い | 決定 4。シェーダーと素材は動かしたまま読み直す |
| Bevy は 1.0 前。公式のエディタは実験段階 | 決定 3。編集画面に頼らず、コードとデータで世界を作る(世界は本物の環境から生成するので相性は良い) |

## 採用しなかった案

- **TypeScript + Three.js + Electron**(0001 の案): 本人の基準(Rust が好き)に合わない。
  起動、メモリ、入力の反応でも不利
- **Rust をブラウザ用に変換して Electron に包む**(100-cord-knocks と同じ形): Rust では書けるが、
  ブラウザの上で動くので、ネイティブの利点(起動、メモリ、入力の反応)が得られない
- **Unity / Unreal / Godot**: Rust で書けない、または Rust が脇役になる

## 未検証(段階 1 で確かめる)

- Bevy の上で、本物のターミナルの内容を表示し、キー入力を遅れなく通せるか
- `alacritty_terminal` が使える形で公開されているか、ライセンスに問題がないか
- 動かしたまま数値・シェーダーを読み直す仕組みが、演出の調整に十分な速さか
- Steam との連携(実績、オーバーレイ)が Bevy で動くか
- 音: Bevy 標準の音の機能で足りるか。足りなければ専用の音の部品を使う
- `prototypes/dive/` と同じ場面を Bevy で作り、起動時間・メモリ・動きの滑らかさを測る

成立しなければ、この決定を見直す。
