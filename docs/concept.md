# コンセプト

最終更新: 2026-11-15

## 一文で

**本物のコマンドとコードを打って、システムの階層に潜り、世界を構築するゲーム。**

遊びは2本柱。

- **潜る**: すでにあるシステムの中に入り、調べ、直す
- **築く**: 本物のコードを書いて、世界(アプリ)そのものを作る

## 芯

- **階層を降りていく感覚**。サーバーに入り、その奥のサーバーへ、さらにコンテナの中へ。深さそのものが主役
- **超現実的な描写**。層ごとに世界の法則が変わる(街が折れ上がる、重力が傾く、街がほどけて漂う)
- **命令を打つと世界が見える**。`ls` で建物に名前が付き、`ps` でプロセスが姿を現す。打つ前は見えない
- **コードを書くと世界ができる**。書いたコードが本物のアプリとして動き、それが世界の一部として姿を現す
- **作業する瞬間は本物**。打つのは本物のコマンドとコードで、本物の Linux で実行される。世界はその結果を映す

## 2つの層

| 層 | 中身 |
|---|---|
| 現実の層 | 依頼を受け、報酬を得て、機材を揃える。依頼 → 作業 → 報酬 → 成長の骨格 |
| 潜る層 | 依頼されたシステムの中に入り、階層を降りる。修理も構築も「潜って、中で何かを変えて、戻る」 |

## 築くミッション

本物のコードを書いて、アプリやシステムを作る。作ったものは本物として動き、世界に現れる。

- **判定は「動くかどうか」**。書いたコードを本物の環境で実行し、依頼どおりに振る舞うかを自動で確かめる
- **潜ると築くはつながる**。自分が築いた世界に、あとから潜れる。築いたものが壊れれば、直しに潜る
- 何もない場所に世界ができていく様子は、PC Building Simulator の「組んだものが動く」に当たる

未定: 使う言語、作るものの規模(関数1つからアプリ全体まで)、エディタの見せ方、
書いたコードを世界のどんな姿に対応させるか。

## 着想元と、借りる範囲

- インセプション: **階層に潜る構造**だけを借りる
- サイバーパンク エッジランナーズ: システムやネットワークの中に実際に入る電脳世界の感覚
- PC Building Simulator: 依頼 → 作業 → 報酬 → 成長の骨格

世界観・人物・物語・見た目はオリジナルで作る。

## 本物の構造との対応

| 潜る世界の出来事 | 本物のシステムで起きていること |
|---|---|
| 下の層へ潜る | `ssh` で奥のサーバーへ、`docker exec` でコンテナの中へ |
| 層ごとに違う世界 | 層ごとに OS もプロセスもファイル構造も違う |
| 上の層へ戻る | `exit`、または接続の切断 |
| 上の層の出来事が下に響く | 親が落ちると中のコンテナも巻き込まれる |
| 侵入者に反応する住人 | 監視や防御の仕組み |
| 奥にある秘密 | 権限の奥にあるデータや設定 |
| 世界の振る舞いを変える | 設定やコードを1行変える |
| 世界を設計して築く | コードを書いてアプリを作り、起動する |

## 「本格的」の意味

1. 見た目と音の完成度
2. 技術的な本物さ
3. 物語と世界観

## ミッションの型

ミッションはデータとして持つ。

1. 準備: 環境をわざと壊す、または空の状態を用意する
2. 依頼文
3. 判定: 直ったか・作れたかを自動で確かめる

分野(ターミナルでの障害対応、コーディング、DB、ネットワークなど)は、ミッションを足すことで増やす。

## 避けたいこと

PC Building Simulator は1作目も続編も「キャリアが単調で同じ作業の繰り返し」と批判されている。
同じ種類の障害を巡回させない。

## まだ決めていないこと

- 舞台と時代、主人公、依頼主などの人物
- 物語の筋
- 経営の層の中身(固定費、評判、解放されるもの)
- 見た目の質感の方向(試作の建物は単純な箱)
