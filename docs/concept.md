# コンセプト

最終更新: 2026-11-15(物語中心に組み直した。創るもの・言語・言葉の方針を追加)

## 一文で

**本物のコマンドとコードで、一つのシステム(世界)を創造する物語。**

## 誰のためのゲームか

エンジニアを目指す人と現役エンジニアが「最高のゲームだ」と思えるゲーム。深い専門性を持つ。

- 最低ライン: プログラミングの入門を一度やった人(変数・関数・条件分岐は分かる。
  ターミナル・サーバー・DB は未経験でよい)。文法は教えない
- **サクサク進む。** 詰まったら、すぐ答えを見られる。答えのコードには、学習にもなるように、
  なぜそう書くのかをコメントで手厚く解説する
- 書く深さは分けない。全員に、関数の名前・テスト・その場面の説明を見せる。書ける人は書き、詰まった人は答えを見る
- **図鑑**: 出会ったコマンドと概念がたまる。「世界ではこう見える」と「本物の技術としてはこう」の両方を載せる。
  読みたい人だけが開く脇役
- 本物を薄めない。導きは本物の横に足すもので、置き換えない

## 芯

- **一つの世界を創造する。** 何もないところから、一つのシステムを作り、育て、守る。
  ゲームを通して同じ一つの世界と付き合う
- **世界を見ていく物語。** クリアを目指すというより、ビジュアルノベルのように世界を見ていく。
  ただしゲームオーバーはある
- **階層を降りていく感覚**と**超現実的な描写**。層ごとに世界の法則が変わる
- **入れ子があるところは、どこでも潜れる。** フォルダからフォルダへ、フォルダからファイルへ、
  ファイルからコードへ、関数から関数へ、機械からその中のコンテナへ。深さに上限はない
- **隣にあるものへは、渡る。** 別の機械へ行くのは潜るではない。潜るは縦、渡るは横
- **技術の概念を、ちゃんと電脳世界として表現する。** フォルダ、ファイル、コード、モジュール、
  インスタンス、データモデル、配列、構造体、API、ネットワーク、DB、HTTP など。
  正しく理解すると、正しく見える
- **命令を打つと世界が見える。コードを書くと世界ができる**
- **作業する瞬間は本物。** 本物のコマンドとコードが、本物の Linux で実行される。世界はその結果を映す
- **実際のシステム開発と全く同じ流れ。** 作る、テストする、デバッグする、運用する、障害に対応する
- **AI を表現する。** AI は自分の能力の拡張として現れる

## 世界に住人はいない

世界にいるのは、構造と、動いているものと、流れだけ。人の姿をしたものは出さない。

## 創るもの

- **0から創る。** 主役は創ること。現場の仕事の再現ではなく、そこまで業務的でなくてよい
- 「0から」は、**何もない状態から新しいシステムを創る**という意味。依存パッケージは普通に使ってよい
  (出来合いの部品を使わず土台から手で積む、という意味ではない)
- **創るのはサーバー**(リクエストを待ち受け、処理し、レスポンスを返し続けるプログラム)と、
  データを覚える仕組み
- **何のためのシステムかは抽象的にする**(方向。未確定)。ただし仕様は具体的に決める:
  データの形、受け取る命令、返す結果、守るべき決まり
- **扱う物の名前は「断片」**(コード上は `Fragment`)

## 言葉の方針

- **技術用語は本物のまま使う。** リクエスト、レスポンス、ポート、DB など。言い換えない
- 世界の言葉を置くのは、扱う物の名前(断片)だけ
- 世界観は、言い換えではなく、見た目と音と物語で作る

## プレイヤーが書く言語

- **基本は TypeScript**
- **Rust モードも用意する**

(ゲーム本体を何で作るかは別の話。`decisions/0002` で Rust + Bevy)

## 遊びの形(決まったこと)

- **書くのは各章の「核」だけ。** その概念の本質が詰まった 10〜40 行を自分で書く。
  周りは、主人公が書き進めたものとして立ち上がる。用意された部分も本物のファイルで、読めて書き換えられる
- **テストは世界の一部として最初からある。** 書き方は強制しない。Red → Green の瞬間は見せ場にする。
  前半で置いたテストが、後半で AI のミスを食い止める
- **AI は作り込む。** 振る舞い・書くコード・犯すミスをあらかじめ設計する。本物の AI にはつながない。
  作り込んだ AI も本物の環境で本物のコマンドを打つ
- **AI の幕はクライマックス。爽快感と無双感。** 作り込んだ見せ場として進み、プレイヤーは要所で
  タイミングよく選ぶ。指示の内容と粒度で、有能なエンジニアらしさを見せる
- **AI の並列作業は、並行世界として見せる。** ブランチは並行世界。世界が写しに分かれ、それぞれで作業が進み、
  マージで一つに重なる
- **最後の一手は、自分の手で。** 前半で自分が書いたデプロイのコマンドを、自分で実行する
- **有能さは指示の文面だけで表現する。** 規則のファイルや一覧のような仕組みは入れない
- **エラーバジェットを見せる。** SLO、残り、バーンレート、グラフを、本物の運用画面と同じ形で出す。
  尽きたらゲームオーバー
- **監視の画面は、自分で創って初めて見える。** それまでは、自分でコマンドを打って調べるしかない
- **崩壊の幕では終わらない。** 追い詰められること自体が物語
- **やり直しは、最後のコミットまで世界が巻き戻る。** 「GAME OVER」の画面は出さない
- **長さ**: 初回クリアまで 4〜6 時間ほど

## 作り込みの要素(主役ではない)

主役は、一つの世界を創る物語。以下は「ここまで手が込んでいるのか」と気づいた人が驚く、作り込みの要素。

**音楽が、世界と同じ動きをする**

- 創造: 章を一つ終えるごとに、曲の断片が一つ増える
- 運用: 障害が起きると、該当するパートが乱れる
- 崩壊: 世界が壊れると、パートが抜け落ちていく
- クライマックス: 並行世界 1 枚にパートを 1 つ。世界が分かれると曲もばらけ、重なるとパートが加わる。
  食い違い(コンフリクト)は不協和音で、解決すると和音になる
- 主題曲が完全な形で鳴るのは、最後の一枚が重なった瞬間の一度だけ

## 物語の骨格

1. **創造**: 一つの世界(システム)を作っていく。デバッグやテストなど、実際の開発と同じ流れで
2. **運用**: バグが発生し、障害に対応する。ログから `grep` で原因を特定し、原因のコードを直す
3. **崩壊**: 対応不可能な危機が訪れ、世界が崩壊し始める。相手は姿を見せず、すべては「外」から来る
   - 押し寄せる: リクエストが桁違いに増え、連鎖的に詰まる。一つ直す間に二つ壊れる
   - 内側から封じられる: 自分の手で入れた依存パッケージがすり替わっていて、断片が読めなくなっていく
   - 頼みの綱が切れる: 自分が用意したバックアップが、復元できない(戻せるかを試していなかった)
4. **拡張**: AI をインストールする。自分の能力の拡張
5. **無双**: 危機に立ち向かう。並列で複数の作業が一気に進み、神の力のような無双感がある。
   ただし AI のミスを指摘し、有能なエンジニアでないと出せない指示を出す腕が要る

6. **結末**: 世界が戻る。最後のコミットメッセージを、プレイヤーが自分の言葉で打つ。
   一番上の層で `exit` を打つと、最初は通らなかったそれが、今度は通る。視点が外へ引いていき、
   自分が創った世界が、もっと大きな何かの一つの部品だったと分かる。一番外側が見える前に暗転

### 結末の意味

- 外から届いていたリクエストは、自分の世界に依存している別の世界からのものだった
- 自分は依存パッケージを入れた側であり、同時に、誰かにとっての依存パッケージでもあった
- 自分が創った世界そのものが、一つの「断片」だった
- 一番外側は見せない

## 語り

- 物語は、エンジニアが実際に書く文章で語る: コミットメッセージ、コードのコメント、README、障害の振り返り。
  `git log` があらすじになる。世界の外から説明を入れない
- 要所だけ、主人公の短い独白
- 主人公は名前も姿も出さない

## 主題(案)

AI は能力の代わりではなく拡張。基礎を知る者だけが使いこなせる。

前半を手で作るから、後半の無双が効く。手で知った基礎があるから、AI のミスを見抜ける。

## 見た目と音の方向(決まったこと)

| | 方向 |
|---|---|
| 構造 | 階層に潜る。巨大で無人の構造物 |
| 絵 | 写実ではなく様式。**文字を絵として使う。** 限られた色と、意味を持つ差し色。素早い切り替え |
| 空気 | 冷たく、孤独で、静か |
| 音 | 前半は静かで音数が少ない。クライマックスで、積み上げて主題が一気に入る |

- コミットメッセージ、エラーの 1 行、ログの 1 行を、単色の画面に文字だけで一瞬出す
- 核が通った後に世界が立ち上がる場面は、コミットメッセージを読み切れない速さで連ねて見せる
- 手触り(速さ、光り方、音の質感)は段階 2 の試作で、基準の絵と曲は段階 4 で決める

## 着想元と、借りる範囲

本人が好きなもの: インセプション、サイバーパンク エッジランナーズ、攻殻機動隊、澤野弘之の曲、SIGNALIS、
物語シリーズの技法。

- インセプション: 階層に潜る構造、一つの世界を設計して作ること
- エッジランナーズ、攻殻機動隊: 電脳世界に入る感覚、能力をインストールする感覚
- 澤野弘之の曲: 静かに積み上げて、主題が一気に入る高揚
- SIGNALIS: 様式で見せる絵、冷たく孤独な無人の空間、文字だけの画面を挟む見せ方
- 物語シリーズ: 文字を絵として使う技法、単色の画面、素早い切り替え

**借りるのは方向と技法だけ。** 特定の作品の絵・曲・人物・場面はなぞらない。世界観・物語・見た目はオリジナルで作る。

## 本物の構造との対応

| 世界の出来事 | 本物のシステムで起きていること |
|---|---|
| 潜る(中に入っているものへ) | フォルダからファイルへ、ファイルから関数へ、関数の呼び出し、`docker exec` でコンテナの中へ |
| 渡る(隣にあるものへ) | `ssh` で別の機械へ。入れ子ではないので、潜るではない |
| 層ごとに違う世界 | 層ごとに OS もプロセスもファイル構造も違う |
| 上の層へ戻る | ファイルを閉じる、関数からの戻り、コンテナから `exit` |
| 上の層の出来事が下に響く | 親が落ちると中のコンテナも巻き込まれる |
| 世界を設計して築く | コードを書いてアプリを作り、起動する |
| 世界の振る舞いを変える | 設定やコードを1行変える |
| 時間を行き来する | git のコミット、ブランチ、巻き戻し |

概念ごとの詳しい対応の案は `ideas.md`。

## 進み方の型

物語の場面ごとに、次の3つをデータとして持つ。

1. 準備: 世界をその場面の状態にする(空の状態、壊れた状態)
2. 物語と課題
3. 判定: 作れたか・直ったかを、本物の環境で自動で確かめる
