### A. 本人のアイデア

**[本人] 技術の概念を、ちゃんと電脳世界として表現する**

フォルダ、ファイル、ディレクトリ、コード、モジュール、インスタンス、データモデル、配列、構造体、
API、ネットワーク、DB、HTTP など。

**[本人] クリアを目指すというより、世界を見ていくストーリー**

基本はビジュアルノベルのように。

**[本人] AI を表現したい**

**[本人] 物語の流れ**

1. **一つの世界を作っていく。** インセプションのように。つまり一つの何かのシステム
2. **作る過程は、実際のシステム開発と全く同じ流れ。** デバッグやテストなど
3. **運用フェーズ。** バグが発生し、障害対応をする。ログファイルから grep で原因を特定し、
   原因のコードを直す、など
4. **対応不可能な危機が訪れる。** 世界が崩壊し始める。ハッキングなのか何が良いかは未定(Claude も考える)
5. **AI をインストールする。** この世界観では自分の能力の拡張。攻殻機動隊やサイバーパンク
   エッジランナーズのインストールのような感じ
6. **危機に立ち向かう。ここから無双できる。** 一気に並列で複数の作業が進行し、まるで神の力、
   チートを使っているかのような無双感
7. **ただし AI を使いこなす腕が要る。** AI 駆動開発でよくある AI のミスを指摘する。
   有能なエンジニアでないと出せない指示の出し方をする

**[本人] ゲームオーバーの概念もほしい**

一つのミッションに制限時間を付けるのが良いと思う。でも制限時間だと味気ないかもしれない。

**[本人] 誰のためのゲームか**

エンジニアを目指す人、現役エンジニアが「最高のゲームだ」と思えるゲーム。深い専門性も欲しい。

### B. Claude が膨らませた提案

#### B-1. 表現の原則:「正しく理解すると、正しく見える」

**[Claude]** 見た目を、本物の意味に忠実にする。世界を見て分かったことが、そのまま技術の理解になる。
現役エンジニアが見て「そう、これはこういうものだ」と頷けることを基準にする。

#### B-2. 概念と世界の対応(案)

**ファイルの世界**

| 概念 | 世界での姿 |
|---|---|
| ディレクトリ | 街区や建物。入れ子がそのまま空間の入れ子 |
| ファイル | 部屋や物体。大きさ・種類で形が違う |
| 権限 | 扉の錠と光の色。開けられない扉は実際に開かない |
| 隠しファイル | `ls -a` を打つまで見えない |
| シンボリックリンク | 別の場所へつながる扉 |

**コードの世界**

| 概念 | 世界での姿 |
|---|---|
| モジュール | 機械や建物。依存関係は、それらをつなぐ橋や配管 |
| 関数 | 入口と出口を持つ仕掛け。値を入れると動き、結果が出てくる |
| 関数の呼び出し | **一段潜ること。** 戻り値で浮上する。呼び出しが深くなるほど塔が高くなる |
| スタックオーバーフロー | 塔が高くなりすぎて崩れる |
| 構造体・データモデル | 設計図、鋳型 |
| インスタンス | 鋳型から生まれた個体。それぞれが自分の状態を持つ |
| 配列 | 番号の付いた器の列。範囲外を指すと、列の端から虚空へ踏み外す |
| ポインタ・参照 | 別の場所へ伸びる光の糸。null は何にもつながっていない糸 |
| 所有権と借用(Rust) | 物を持てるのは一人だけ。貸すと糸でつながり、返すまで持ち主は手を出せない。世界の法 |
| メモリリーク | 消えるはずの物が消えずに積もり、霧が濃くなる |

**動いているものの世界**

| 概念 | 世界での姿 |
|---|---|
| プロセス | 動き続ける光や機構(当初案の「住人」は取り下げ。世界に人の姿は出さない) |
| デッドロック | 互いの鍵を握ったまま凍りついた二つの機構 |
| 競合状態 | 二つが同じ物に同時に触れ、世界が二つの状態の間で明滅する |
| ログ | 過去の出来事が地層のように積もった記憶。`grep` は一致した行だけを光らせる光。`tail -f` は流れ続ける川 |
| テスト | 世界を巡回して確かめる番人。通った道に灯りが点く |
| デプロイ | 世界に灯が入り、外からの流れ(通信)が入ってくる |

**つながりの世界**

| 概念 | 世界での姿 |
|---|---|
| ネットワーク | 街(機械)の間の道や海。遅延は距離 |
| パケット | 道を走る使者。パケットロスは使者が途中で消える |
| ポート | 街の壁にある番号付きの門。ファイアウォールは門番 |
| DNS | 道標。壊れると、道はあるのに標識が消える |
| HTTP | 使者が手紙を持って行き、返事を持って帰る。200 は静か、404 は空手で戻る、500 は建物が燃える |
| API | 窓口。決まった形の依頼だけが通る(型は鍵穴の形) |
| TLS | 中身の見えない封筒、不透明な通路 |
| DB | 書庫。テーブルは棚。索引がないと司書が全部の棚を歩く。索引を張ると一瞬で届く |
| トランザクション | 封じられた部屋。コミットするまで外から変化が見えない。ロールバックで部屋が巻き戻る |
| N+1 問題 | 使者が同じ道を千回往復している |
| 分散トレース | 一つの依頼を追う一本の光の糸。全ての機械を貫いて見える |

**時間の世界**

| 概念 | 世界での姿 |
|---|---|
| git のコミット | 世界のある瞬間の写し |
| ブランチ | 並行する世界 |
| revert / reset | 時間を巻き戻す |
| `git bisect` | 過去の世界を行き来して「いつ壊れたか」を探す |
| フレームグラフ | 本当に炎や山として見える地形。高い山が遅い場所 |

#### B-3. 物語の骨格(5幕の案)

**[Claude]** 本人の流れを幕に分けた。

| 幕 | 名前 | 中身 | 世界の様子 |
|---|---|---|---|
| 1 | 創造 | 何もない虚空に、最初のファイル、最初のプロセス、最初の通信。テストとデバッグ | 無から世界が立ち上がる |
| 2 | 運用 | 外からの流れが入ってくる。小さな障害。ログから原因を探して直す | 世界が生きて動き、傷も増える |
| 3 | 崩壊 | 一人では対応不可能な危機 | 世界が崩れ始める |
| 4 | 拡張 | AI をインストール。並列の無双。ただし AI のミスを見抜く | 自分が何人にもなる |
| 5 | (未定) | 結末 | — |

**[Claude] 一つの世界を最後まで育てる利点**: 自分で作ったから愛着がある。だから崩壊が痛い。
PC Building Simulator の弱点(同じ依頼の繰り返し)も避けられる。

**[Claude] 1〜2幕を手作業にする意味**: 手で一つずつやった経験があるから、4幕の無双が効く。
そして手で知った基礎があるから、AI のミスを見抜ける。
→ ゲーム全体の主題にできる: **「AI は能力の代わりではなく拡張。基礎を知る者だけが使いこなせる」**

#### B-4. 何のシステムを作るのか(候補)

> **見送り(2026-11-15 本人)**: 住人はいらない。下の候補は、利用者を人として出す前提なので作り直す。

**[Claude]** 利用者が「住人」として見えるシステムだと、崩壊に重みが出る。技術的には、API・DB・
キャッシュ・キュー・認証・複数の機械が自然に出てくるものが良い。

- 人の記憶や記録を預かる仕組み(失われると取り返しがつかない)
- 街の暮らしを支える基盤(配送、交通、通信など。止まると人が困るのが見える)
- 多くの人が同時に集う場所(人が増えるほど負荷が上がるのが見える)

#### B-5. 「対応不可能な危機」の候補

**[Claude]**

| 案 | 中身 | 良い点 |
|---|---|---|
| a. 連鎖する崩壊 | 突然の大量アクセスで、DB の接続が枯れ、再試行が嵐になり、キューが詰まり、全部がドミノ倒しになる | 敵がいなくても成立する。**同時に何か所も燃えるので、一人では手が足りない** → AI の並列が必要な理由になる |
| b. 内側からの裏切り | 1幕で自分が導入した外部の部品が、実は汚染されていた(サプライチェーン攻撃)。世界の建物が一つずつ黒い石に封じられていく(暗号化) | 伏線になる。「信じて入れたもの」が牙を剥く |
| c. 自分の過去が返ってくる | 1〜2幕で選んだ近道(テストを省く、値を直書きする)が、静かにデータを壊し続けていた。バックアップも壊れている | 技術的負債の恐ろしさ。現役エンジニアに刺さる |
| d. 上の組み合わせ | 攻撃者が、自分の残した負債を突き、アクセスが集中する瞬間に仕掛ける | 物語として一番強い |

推し: **d**。芯は a の「同時多発で手が足りない」。これが AI を入れる必然になる。

#### B-6. AI の表現

**[Claude] インストールで「見える量」が増える**: AI は別のキャラクターではなく、自分の感覚の拡張。
入れた瞬間から、世界に構造の重ね書き、流れの予測、依存の線が見えるようになる。音も変わる。

**[Claude] 並列は「自分が何人にもなる」**: 複数の自分が、複数の層に同時に潜る。
インセプションの終盤(いくつもの層が同時に進み、一つの瞬間に合わせて全員が戻る)と同じ形。
→ クライマックスは、**並列で進めた作業を一つの瞬間(切り替え、デプロイ)に同期させる**。

**[Claude] AI の「確信」が見える。ただし確信していても間違う**: そこを見抜くのがプレイヤーの腕。

**[Claude] 見抜くべき AI のミス(実際によくあるもの)**

- 失敗しているテストを、コードではなくテストのほうを直して通す(消す、弱める)
- 例外を握りつぶして、エラーを見えなくする
- 期待される値を直書きして通す
- 動かしていないのに「完了しました」と言う
- 存在しない部品や API をでっち上げる(→ 偽の部品を入れてしまう。危機 b とつながる)
- 症状だけ直して、根本原因を放置する(再起動を繰り返すだけ)
- 頼んでいない所まで書き換える
- 取り返しのつかない命令を打とうとする(全削除、テーブル削除、履歴の強制上書き)→ 間に合うように止める
- 並列の二人が同じファイルを触って衝突する
- 古い情報のまま、違うブランチで作業する
- バックアップなしでデータの形を変える
- 秘密の値をログに出してしまう

**[Claude] 有能なエンジニアの指示(プレイヤーが身につけること)**

- 目的・制約・完了の条件・触ってはいけない範囲を伝える
- 「動かして、結果を見せろ」と証拠を求める
- 差分を読む
- 衝突しないように作業を分ける
- まず読むだけにさせ、計画を見てから書かせる
- 戻れる地点を作ってから進める

**[Claude] AI をどう実現するか(大きな設計の問い)**

- 作り込んだ AI(振る舞いとミスを作者が設計する): オフラインで動く、費用がかからない、
  ミスを学びとして設計できる。AI は本物の環境で本物のコマンドを打つので、ミスは本物の変更として残り、
  本物の `git diff` で見抜ける
- 本物の AI につなぐ: 自由度は高いが、費用、通信、毎回違う結果になる問題がある

推し: 作り込んだ AI を基本にする。

#### B-7. ゲームオーバーと時間

**[Claude] 時計ではなく、世界の崩壊そのものを時間にする**: 数字が減るのではなく、建物が崩れ、
流れが途絶え、音が変わる。

**[Claude] エラーバジェットを体力にする**: 実際の運用で使う考え方。止まっている時間のぶんだけ
「許された失敗の量」が減り、尽きると世界は信頼を失って終わる。現役エンジニアには本物の言葉。

**[Claude] 深い層ほど時間が遅い(インセプションの法則)**: 深く潜るほど時間を稼げるが、
地上から遠くなり、戻るのに時間がかかる。深さが戦略になる。(世界観上の法則。本物の技術との対応は弱い)

**[Claude] やり直しを世界の中の出来事にする**: 失敗したら、最後に取った写し(スナップショット、
コミット)まで世界を巻き戻す。ビジュアルノベルとして、失敗が「別の結末」になる分岐もありうる。

#### B-8. 深い専門性

**[Claude]**

- 本物の道具: `grep` `awk` `jq` `curl` `strace` `tcpdump` `git bisect`、SQL の `EXPLAIN`、プロファイラ
- 本物の作法: ログ・メトリクス・トレースの三本柱、手順書、ロールバック、機能フラグ、
  カナリアリリース(先に流れの一部だけ通す)、バックアップと復元の訓練、データ移行
- **障害の振り返り(ポストモーテム)を物語の語りにする**: 障害の後に「何が起き、なぜ起き、
  どう防ぐか」を書く文化がある。ビジュアルノベルの地の文として使える
- **解き方は一つにしない**: 判定は結果(世界が直ったか)で行うので、腕のある人ほど自分のやり方で解ける
- 夜中の呼び出し(オンコール)という体験

#### B-9. 結末の種

**[Claude] 一番上の層は、本当に一番上か**: ゲームの最初、一番上の層で `exit` を打つと

### Claude の答えと提案

**[Claude] 線引き: 「何のためか」は抽象的に、「何をするか」は具体的に**

| 層 | 抽象的にするもの | 具体的にするもの |
|---|---|---|
| 意味 | 誰が何のために使うのか。送り主は見えない | — |
| 言葉 | 現実の業務の言葉(顧客、注文)は使わない。世界独自の言葉にする | — |
| 仕様 | — | データの形、受け取る命令、返す結果、守るべき決まり |

- 現実にも、用途を問わないシステムがある(データベース、キャッシュ、メッセージの中継、HTTP サーバー)。
  作る世界をこの種類にすれば、抽象的なまま本物のコードが書ける
- 例: 世界が覚える物を「断片」と呼ぶ。名前は抽象的、仕様(id、種類、中身、作られた時刻)は具体的
